ผู้รับผิดชอบ เจ้าของข้อมูล (Data Owner) / ฝ่ายเทคโนโลยีสารสนเทศ / Information Security Officer
รอบทบทวน อย่างน้อยปีละ 1 ครั้ง หรือเมื่อมีการเปลี่ยนแปลงที่สำคัญ
การจัดประเภทเอกสาร ภายในองค์กร (Internal)

1. วัตถุประสงค์

มาตรฐานฉบับนี้กำหนดกรอบการจัดประเภทข้อมูล แนวทางการจัดการตามระดับความลับ และหน้าที่ของผู้เกี่ยวข้อง เพื่อ

  1. ให้ข้อมูลขององค์กรได้รับการจัดประเภทอย่างสม่ำเสมอและเข้าใจตรงกัน
  2. กำหนดมาตรการปกป้องที่เหมาะสมกับระดับความเสี่ยงของข้อมูล
  3. ลดโอกาสการเปิดเผย สูญหาย แก้ไขโดยไม่ได้รับอนุญาต หรือใช้ข้อมูลผิดวัตถุประสงค์
  4. สนับสนุนการปฏิบัติตาม POL-ITSEC-001, พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 และหลักการ ISO/IEC 27001/27002

2. ขอบเขต

มาตรฐานนี้ใช้กับข้อมูลทุกรูปแบบที่องค์กรเป็นเจ้าของ ครอบครอง ประมวลผล ส่งต่อ หรือจัดเก็บ รวมถึง

  • ข้อมูลอิเล็กทรอนิกส์ กระดาษ ภาพ เสียง และข้อมูลในระบบคลาวด์
  • ข้อมูลธุรกิจ ข้อมูลส่วนบุคคล ข้อมูลเทคนิค และข้อมูลความลับทางการค้า
  • ข้อมูลที่สร้างโดยพนักงาน ผู้รับจ้าง พันธมิตร หรือระบบขององค์กร
  • ข้อมูลที่อยู่กับผู้ให้บริการภายนอกซึ่งประมวลผลแทนองค์กร

3. นิยามศัพท์

คำศัพท์ ความหมาย
การจัดประเภทข้อมูล (Data Classification) การกำหนดระดับความลับ/ความสำคัญของข้อมูลเพื่อเลือกมาตรการปกป้องที่เหมาะสม
เจ้าของข้อมูล (Data Owner) ผู้รับผิดชอบทางธุรกิจต่อชุดข้อมูล มีอำนาจอนุมัติการเข้าถึงและการจัดประเภท
ผู้ดูแลข้อมูล (Data Custodian) ผู้ดูแลระบบ/คลังข้อมูลที่เก็บรักษาและบังคับใช้มาตรการปกป้องตามที่เจ้าของข้อมูลกำหนด
ผู้ใช้ข้อมูล (Data User) ผู้ที่ได้รับอนุญาตให้เข้าถึงหรือใช้ข้อมูลตามหน้าที่
ข้อมูลส่วนบุคคล ข้อมูลเกี่ยวกับบุคคลซึ่งทำให้สามารถระบุตัวบุคคลนั้นได้ตาม PDPA
ข้อมูลส่วนบุคคลอ่อนไหว ข้อมูลส่วนบุคคลประเภทอ่อนไหวตามที่กฎหมายกำหนด เช่น เชื้อชาติ ความเชื่อ สุขภาพ พฤติกรรมทางเพศ ประวัติอาชญากรรม ข้อมูลชีวภาพ
Need-to-Know หลักการให้เข้าถึงเฉพาะผู้ที่จำเป็นต่องานเท่านั้น
การทำให้ข้อมูลไม่ระบุตัวตน (Anonymization) การทำให้ไม่สามารถระบุตัวบุคคลได้อีก
การลดความละเอียดของข้อมูล (Pseudonymization / Masking) การแทนค่าหรือปกปิดบางส่วน เพื่อลดความเสี่ยงแต่ยังเชื่อมโยงกลับได้ภายใต้เงื่อนไข

4. ระดับการจัดประเภทข้อมูล

องค์กรกำหนด 4 ระดับ ดังนี้

ระดับ ภาษาอังกฤษ ความหมายโดยสรุป
ลับที่สุด Restricted หากรั่วไหลหรือถูกทำลายจะเกิดผลกระทบร้ายแรงต่อองค์กร ลูกค้า กฎหมาย หรือความมั่นคงของระบบ
ลับ Confidential หากรั่วไหลจะเกิดผลกระทบสูงต่อธุรกิจ ความน่าเชื่อถือ หรือสิทธิของบุคคล
ภายใน Internal ใช้ภายในองค์กร หากรั่วไหลมีผลกระทบจำกัด
สาธารณะ Public เผยแพร่ได้โดยทั่วไป และไม่ก่อให้เกิดความเสียหายหากเปิดเผย

หากข้อมูลชุดหนึ่งประกอบด้วยหลายระดับ ให้จัดประเภทตาม ระดับสูงสุด ที่มีอยู่ในชุดข้อมูลนั้น

5. เกณฑ์การพิจารณาจัดประเภท

ให้พิจารณาอย่างน้อยตามมิติต่อไปนี้

  1. ผลกระทบทางธุรกิจ — การเงิน ชื่อเสียง การแข่งขัน การดำเนินงานต่อเนื่อง
  2. ผลกระทบต่อเจ้าของข้อมูล/ลูกค้า — ความเสียหายต่อสิทธิ เสรีภาพ หรือความเป็นส่วนตัว
  3. ข้อกำหนดทางกฎหมายและสัญญา — PDPA ความลับตามสัญญา ใบอนุญาต ข้อกำหนดคู่ค้า
  4. ความสำคัญต่อระบบ — คีย์เข้ารหัส การตั้งค่าความปลอดภัย แผนกู้คืน
  5. ขอบเขตการเผยแพร่ที่ตั้งใจ — เผยแพร่สาธารณะ ใช้ภายใน หรือจำกัดเฉพาะกลุ่ม

5.1 ตารางผลกระทบโดยย่อ

หากเกิดการรั่วไหล/เสียหาย ระดับที่ควรพิจารณา
กระทบกว้าง ผิดกฎหมาย มีโทษ เสียหายรุนแรง หรือกระทบโครงสร้างพื้นฐานสำคัญ ลับที่สุด
กระทบธุรกิจหรือสิทธิบุคคลอย่างมีนัยสำคัญ แต่ควบคุมวงจำกัดได้ ลับ
กระทบเฉพาะภายในองค์กรหรือเสียหายต่ำ ภายใน
ไม่ก่อความเสียหาย หรือตั้งใจให้เผยแพร่ สาธารณะ

6. ตัวอย่างข้อมูลในแต่ละระดับ

6.1 ลับที่สุด (Restricted)

  • ข้อมูลส่วนบุคคลอ่อนไหว (สุขภาพ ชีวภาพ ศาสนา ประวัติอาชญากรรม ฯลฯ)
  • หมายเลขบัตรประชาชน / หนังสือเดินทาง คู่กับข้อมูลอื่นที่ระบุตัวตนได้ในบริบทที่มีความเสี่ยงสูง
  • ข้อมูลการเงินสำคัญ เช่น บัญชีเงินเดือนทั้งชุด ข้อมูลบัตรชำระเงิน ข้อมูลบัญชีธนาคารลูกค้า
  • กุญแจเข้ารหัส ใบรับรองส่วนตัว MFA seed และ credential สิทธิพิเศษ
  • ซอร์สโค้ดหรือการตั้งค่าที่เกี่ยวข้องโดยตรงกับความปลอดภัยของระบบผลิต (production security config)
  • เอกสารสอบสวนเหตุละเมิด ความลับทางการค้าขั้นสูง แผนควบรวมกิจการที่ยังไม่เปิดเผย

6.2 ลับ (Confidential)

  • ข้อมูลส่วนบุคคลทั่วไปของพนักงาน ลูกค้า คู่ค้า (ชื่อ ที่อยู่ อีเมล เบอร์โทร ในฐานข้อมูลงาน)
  • สัญญา ราคา ต้นทุน ข้อเสนอทางธุรกิจที่ยังไม่สาธารณะ
  • รายงานทางการเงินภายในก่อนเผยแพร่
  • บันทึกการประเมินผลการทำงาน ข้อมูล HR ที่ไม่ถึงขั้นอ่อนไหวตามกฎหมาย
  • แผนการตลาด ข้อมูลลูกค้ารายชื่อเชิงธุรกิจ บันทึกการเจรจา

6.3 ภายใน (Internal)

  • คู่มือปฏิบัติงานภายใน นโยบาย ระเบียบที่ไม่ใช่เอกสารสาธารณะ
  • ประกาศภายในองค์กร ตารางเวร แผนการประชุมทั่วไป
  • เอกสารโครงการภายในที่ไม่เปิดเผยต่อภายนอก
  • สถิติรวมภายในที่ไม่ระบุตัวบุคคลและไม่ใช่ความลับทางธุรกิจสูง

6.4 สาธารณะ (Public)

  • ข่าวประชาสัมพันธ์ที่อนุมัติแล้ว
  • ข้อมูลผลิตภัณฑ์/บริการที่เผยแพร่บนเว็บไซต์
  • ประกาศรับสมัครงานสาธารณะ
  • เอกสารเผยแพร่ที่ผ่านการตรวจสอบจากหน่วยงานที่รับผิดชอบ

7. บทบาทและหน้าที่

7.1 เจ้าของข้อมูล (Data Owner)

  1. กำหนดและอนุมัติระดับการจัดประเภทของชุดข้อมูลในความรับผิดชอบ
  2. อนุมัติสิทธิ์การเข้าถึงตาม Need-to-Know
  3. ทบทวนการจัดประเภทอย่างน้อยปีละ 1 ครั้ง หรือเมื่อข้อมูลเปลี่ยนบริบท
  4. ประสานงานเมื่อเกิดเหตุรั่วไหลหรือมีคำขอใช้สิทธิของเจ้าของข้อมูลส่วนบุคคล

7.2 ผู้ดูแลข้อมูล (Data Custodian)

  1. จัดเก็บ สำรอง เข้ารหัส และควบคุมการเข้าถึงตามระดับที่กำหนด
  2. ดูแลการติดฉลาก (label) ในระบบและเอกสารตามที่ทำได้
  3. สนับสนุนการตรวจสอบ log และการกู้คืนข้อมูล

7.3 ผู้ใช้ข้อมูล (Data User)

  1. ใช้ข้อมูลเฉพาะตามหน้าที่และวัตถุประสงค์ที่ได้รับอนุญาต
  2. ไม่ส่งต่อ เปิดเผย หรือจัดเก็บข้อมูลผิดระดับหรือผิดช่องทาง
  3. รายงานเหตุสงสัยว่าข้อมูลรั่วไหลหรือจัดประเภทผิด

7.4 ฝ่าย IT / ISO / DPO

  1. กำหนดเครื่องมือ มาตรฐานเทคนิค และแนวปฏิบัติสนับสนุน
  2. ให้คำปรึกษาการจัดประเภทและการคุ้มครองข้อมูลส่วนบุคคล
  3. ตรวจสอบการปฏิบัติตามมาตรฐานเป็นระยะ

8. การติดฉลากและการระบุระดับ (Labeling)

  1. เอกสารและไฟล์ระดับ ลับ และ ลับที่สุด ต้องระบุระดับความลับให้เห็นชัดในหัวเอกสาร ส่วนท้าย หรือ metadata
  2. อีเมลที่มีข้อมูลระดับลับขึ้นไป ควรระบุระดับในหัวข้อหรือเนื้อหา เช่น [ลับ] [ลับที่สุด]
  3. ระบบที่รองรับ sensitivity label / classification tag ต้องใช้ป้ายกำกับให้สอดคล้องกับมาตรฐานนี้
  4. เอกสารสาธารณะไม่จำเป็นต้องติดฉลาก แต่ต้องผ่านการอนุมัติเผยแพร่ก่อน
  5. หากไม่แน่ใจระดับ ให้จัดเป็น ลับ ไว้ก่อน จนกว่าเจ้าของข้อมูลจะยืนยัน

9. แนวทางการจัดการตามระดับ (Handling Rules)

9.1 สรุปมาตรการตามระดับ

หัวข้อ สาธารณะ ภายใน ลับ ลับที่สุด
การเข้าถึง ทั่วไป พนักงาน/ผู้ได้รับอนุญาต Need-to-Know Need-to-Know เข้มงวด + อนุมัติเจ้าของข้อมูล
การจัดเก็บ ตามความเหมาะสม ระบบองค์กร ระบบองค์กรที่ควบคุมสิทธิ์ ระบบควบคุมสิทธิ์ + เข้ารหัส
การส่งผ่าน ไม่จำกัดพิเศษ ช่องทางองค์กร ช่องทางเข้ารหัสที่อนุมัติ ช่องทางเข้ารหัสที่อนุมัติ + จำกัดผู้รับ
การแชร์ภายนอก ได้ โดยหลักแล้วไม่ได้ ต้องมีสัญญา/อนุมัติ โดยหลักแล้วห้าม เว้นแต่จำเป็นและอนุมัติสูง
การพิมพ์/สำเนา ได้ ได้ตามงาน จำกัดและควบคุมสำเนา ห้ามเว้นแต่จำเป็นและบันทึก
การทำลาย ตามปกติ ทำลายเมื่อหมดอายุใช้งาน ทำลายเชิงความปลอดภัย ทำลายเชิงความปลอดภัยและบันทึก

9.2 รายละเอียดการจัดเก็บ

  1. สาธารณะ / ภายใน — เก็บในที่เก็บขององค์กรที่ได้รับอนุญาต
  2. ลับ — เก็บในระบบที่มีการควบคุมสิทธิ์ แนะนำเข้ารหัสขณะจัดเก็บ
  3. ลับที่สุด — ต้องเข้ารหัสขณะจัดเก็บและจำกัดสิทธิ์เฉพาะรายที่ได้รับอนุมัติ มีบันทึกการเข้าถึงตามความเหมาะสม
  4. ห้ามเก็บข้อมูลระดับลับขึ้นไปใน USB ส่วนตัว อีเมลส่วนตัว คลาวด์ส่วนบุคคล หรือเครื่องที่ไม่ได้เข้ารหัสโดยไม่ได้รับอนุมัติ

9.3 รายละเอียดการส่งผ่านและแบ่งปัน

  1. ใช้ช่องทางที่องค์กรอนุมัติเท่านั้นสำหรับข้อมูลระดับภายในขึ้นไป
  2. ข้อมูลระดับลับขึ้นไปต้องส่งผ่านช่องทางเข้ารหัส เช่น HTTPS, SFTP, อีเมลที่เข้ารหัส หรือลิงก์จากระบบแชร์ไฟล์ที่ควบคุมสิทธิ์
  3. ก่อนส่งภายนอก ต้องตรวจสอบผู้รับ วัตถุประสงค์ และระดับการอนุมัติ
  4. ห้ามโพสต์ข้อมูลระดับภายในขึ้นไปบนโซเชียลมีเดียหรือฟอรัมสาธารณะ
  5. ห้ามป้อนข้อมูลระดับลับขึ้นไปเข้าเครื่องมือ AI / แชทบอทสาธารณะที่องค์กรไม่อนุมัติ

9.4 การใช้งานบนอุปกรณ์และพื้นที่ทำงาน

  1. เปิดหน้าจอข้อมูลลับเมื่อมีผู้ไม่เกี่ยวข้องอยู่ใกล้ ควรใช้ privacy screen หรือหลีกเลี่ยงการเปิดเผย
  2. ล็อกเครื่องทุกครั้งที่ไม่อยู่หน้าจอ
  3. เอกสารกระดาษระดับลับขึ้นไปต้องไม่ทิ้งไว้บนโต๊ะโดยไม่มีผู้ดูแล และเก็บในตู้ที่ล็อกได้
  4. เมื่อทำงานนอกสถานที่ ต้องระวังการมองข้ามไหล่และการเชื่อมต่อเครือข่ายที่ไม่ปลอดภัย

10. ข้อมูลส่วนบุคคลและ PDPA

  1. ข้อมูลส่วนบุคคลอย่างน้อยต้องจัดเป็นระดับ ลับ
  2. ข้อมูลส่วนบุคคลอ่อนไหวต้องจัดเป็นระดับ ลับที่สุด
  3. เก็บ ใช้ เปิดเผยเท่าที่จำเป็นตามวัตถุประสงค์ที่ชอบด้วยกฎหมาย
  4. หากใช้ข้อมูลส่วนบุคคลในสภาพแวดล้อมทดสอบ/พัฒนา ต้องทำ anonymization หรือ masking ให้เหมาะสมก่อน
  5. เมื่อเกิดเหตุละเมิดข้อมูลส่วนบุคคล ให้แจ้ง DPO / ช่องทางที่กำหนดทันที เพื่อประเมินการแจ้งตามกฎหมาย

11. วงจรชีวิตข้อมูล (Data Lifecycle)

ขั้นตอน ข้อกำหนดหลัก
สร้าง/รับข้อมูล จัดประเภททันทีหรือภายในระยะเวลาที่กำหนด และระบุเจ้าของข้อมูล
จัดเก็บ ใช้ที่เก็บตามระดับ พร้อมสิทธิ์และการเข้ารหัสที่เหมาะสม
ใช้/ประมวลผล ใช้ตามวัตถุประสงค์และสิทธิ์ที่ได้รับ
แบ่งปัน ตรวจระดับ ผู้รับ ช่องทาง และการอนุมัติ
โอนย้าย/ส่งออก ประเมินความเสี่ยงและข้อกฎหมายก่อนโอน โดยเฉพาะการโอนข้ามประเทศ
เก็บรักษา เก็บเท่าที่จำเป็นตามกฎหมาย นโยบาย หรือสัญญา
ทำลาย/ทำให้หมดสภาพ ทำลายตามระดับความลับ และบันทึกเมื่อเป็นข้อมูลระดับลับที่สุด

11.1 แนวทางการทำลายข้อมูล

สื่อ แนวทาง
ไฟล์อิเล็กทรอนิกส์ ลบอย่างปลอดภัยหรือทำ cryptographic erase ตามที่ระบบรองรับ
ฮาร์ดดิสก์/SSD ที่เลิกใช้ ล้างข้อมูลตามมาตรฐาน หรือทำลายสื่อเมื่อจำเป็น
กระดาษ ใช้เครื่องทำลายเอกสารระดับที่เหมาะสม หรือบริการทำลายที่ได้ใบรับรอง
สื่อสำรอง ควบคุมและทำลายตามรอบอายุของข้อมูลต้นทาง

12. การจัดประเภทในระบบและโครงการ

  1. ระบบใหม่ต้องระบุประเภทข้อมูลที่ประมวลผลตั้งแต่ขั้นตอนออกแบบ
  2. บันทึก data inventory / data asset register สำหรับชุดข้อมูลสำคัญ อย่างน้อยระบุ: ชื่อชุดข้อมูล เจ้าของข้อมูล ระดับ ตำแหน่งจัดเก็บ ผู้มีสิทธิ์ และระยะเวลาเก็บรักษา
  3. ก่อนเชื่อมต่อกับผู้ให้บริการภายนอก ต้องประเมินว่าข้อมูลระดับใดจะถูกประมวลผล และกำหนดข้อสัญญาให้สอดคล้อง
  4. หากพบว่าจัดประเภทต่ำเกินไป ให้ยกระดับทันทีและปรับสิทธิ์/มาตรการตามระดับใหม่

13. การขอยกเว้น

  1. การขอยกเว้นจากมาตรฐานนี้ต้องระบุเหตุผล ระยะเวลา มาตรการชดเชย และผู้รับผิดชอบ
  2. ต้องได้รับอนุมัติจากเจ้าของข้อมูลและ ISO / ผู้จัดการฝ่าย IT
  3. ทบทวนการยกเว้นอย่างน้อยทุก 90 วัน

14. การตรวจสอบและการวัดผล

ตัวชี้วัด เป้าหมายแนะนำ
ชุดข้อมูลสำคัญที่มีเจ้าของข้อมูลชัดเจน 100% ของชุดข้อมูลในทะเบียน
เอกสาร/ระบบสำคัญที่มีป้ายระดับความลับ เพิ่มขึ้นต่อเนื่องจนครอบคลุมครบ
เหตุการณ์แบ่งปันข้อมูลผิดระดับ ลดลง และมี corrective action
การใช้ข้อมูลส่วนบุคคลในระบบทดสอบโดยไม่ masking 0 รายการที่ไม่ได้รับอนุมัติ

15. การบังคับใช้

การฝ่าฝืนมาตรฐานนี้อาจถูกระงับสิทธิ์การเข้าถึงข้อมูล ดำเนินการทางวินัยตามระเบียบองค์กร และ/หรือดำเนินการตามกฎหมาย โดยเฉพาะกรณีจงใจเปิดเผยข้อมูลระดับลับ/ลับที่สุด หรือนำข้อมูลส่วนบุคคลไปใช้ผิดวัตถุประสงค์

16. เอกสารอ้างอิง

  • POL-ITSEC-001 นโยบายการรักษาความปลอดภัยระบบเทคโนโลยีสารสนเทศ
  • STD-ITSEC-001 มาตรฐานรหัสผ่านและการพิสูจน์ตัวตน
  • ISO/IEC 27001:2022 / ISO/IEC 27002:2022
  • พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
  • พ.ร.บ.การรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. 2562

17. ประวัติการปรับปรุงเอกสาร

เวอร์ชัน วันที่ ผู้จัดทำ/แก้ไข สรุปการเปลี่ยนแปลง ผู้อนุมัติ
1.0 [ระบุวันที่] [ชื่อผู้จัดทำ] จัดทำเอกสารฉบับแรก [ชื่อผู้อนุมัติ]

18. ภาคผนวก ก — แผนผังตัดสินใจอย่างย่อ

  1. ข้อมูลตั้งใจเผยแพร่สาธารณะและผ่านการอนุมัติแล้วหรือไม่
    • ใช่ → สาธารณะ
  2. เป็นข้อมูลส่วนบุคคลอ่อนไหว คีย์ความปลอดภัย หรือข้อมูลที่รั่วแล้วเสียหายรุนแรงหรือไม่
    • ใช่ → ลับที่สุด
  3. เป็นข้อมูลส่วนบุคคลทั่วไป สัญญา ข้อมูลธุรกิจที่ไม่สาธารณะ หรือไม่
    • ใช่ → ลับ
  4. ใช้ภายในองค์กรเป็นหลักหรือไม่
    • ใช่ → ภายใน
  5. หากยังไม่แน่ใจ → จัดเป็น ลับ ชั่วคราว แล้วให้เจ้าของข้อมูลยืนยัน

19. ภาคผนวก ข — รายการตรวจสอบสำหรับเจ้าของข้อมูล

20. ภาคผนวก ค — ตัวอย่างข้อความติดฉลาก

[สาธารณะ] เผยแพร่ได้
[ภายใน] สำหรับใช้ภายในองค์กรเท่านั้น
[ลับ] ห้ามเปิดเผยโดยไม่ได้รับอนุญาต — Need-to-Know
[ลับที่สุด] จำกัดสิทธิ์สูงสุด — ต้องได้รับอนุมัติจากเจ้าของข้อมูลก่อนเข้าถึงหรือส่งต่อ

เอกสารนี้เป็นทรัพย์สินขององค์กร ห้ามทำสำเนาหรือเผยแพร่ภายนอกโดยไม่ได้รับอนุญาต
