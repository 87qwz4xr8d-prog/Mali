# แผนความต่อเนื่องทางธุรกิจและกู้คืนจากภัยพิบัติ
## Business Continuity and Disaster Recovery Plan (BCP/DRP)

| รายการ | รายละเอียด |
|--------|------------|
| **รหัสเอกสาร** | PROC-BCP-001 |
| **เวอร์ชัน** | 1.0 |
| **วันที่มีผลบังคับใช้** | [ระบุวันที่] |
| **เอกสารแม่** | POL-ITSEC-001 นโยบายการรักษาความปลอดภัยระบบเทคโนโลยีสารสนเทศ |
| **เอกสารที่เกี่ยวข้อง** | PROC-IR-001, STD-ITSEC-002, PROC-IAM-001 |
| **ผู้อนุมัติ** | [ผู้บริหารสูงสุด / คณะกรรมการบริหารความต่อเนื่อง] |
| **ผู้รับผิดชอบ** | Business Continuity Coordinator / ฝ่ายเทคโนโลยีสารสนเทศ |
| **รอบทบทวน** | อย่างน้อยปีละ 1 ครั้ง หรือหลังการซ้อม/เกิดเหตุจริง |
| **การจัดประเภทเอกสาร** | ภายในองค์กร (Internal) |

> แผนนี้ครอบคลุมการรับมือ**ภัยธรรมชาติ** (น้ำท่วม พายุ แผ่นดินไหว อัคคีภัยจากธรรมชาติ ฯลฯ) และภัยพิบัติอื่นที่กระทบการดำเนินงาน เช่น ไฟไหม้ ไฟฟ้าดับระยะยาว ระบบศูนย์ข้อมูลล่ม และภัยไซเบอร์รุนแรง

---

## 1. วัตถุประสงค์

1. ให้กระบวนการธุรกิจที่สำคัญดำเนินต่อไปได้ในระดับที่ยอมรับได้เมื่อเกิดเหตุขัดข้องหรือภัยพิบัติ
2. กำหนดแนวทางอพยพ ป้องกันชีวิต และสื่อสารฉุกเฉินเมื่อเกิดภัยธรรมชาติ
3. กู้คืนระบบสารสนเทศ ข้อมูล และสถานที่ปฏิบัติงานภายในเป้าหมายเวลาที่กำหนด (RTO/RPO)
4. ลดผลกระทบต่อลูกค้า พนักงาน คู่ค้า และชื่อเสียงขององค์กร
5. สนับสนุนการปฏิบัติตาม POL-ITSEC-001 และข้อกำหนดทางกฎหมาย/สัญญาที่เกี่ยวข้อง

---

## 2. ขอบเขต

### 2.1 อยู่ในขอบเขต
- กระบวนการธุรกิจสำคัญ (Critical Business Processes)
- ระบบสารสนเทศ เครือข่าย ศูนย์ข้อมูล คลาวด์ และข้อมูลสำรอง
- สถานที่ทำงานหลัก สถานที่สำรอง และช่องทางทำงานระยะไกล
- พนักงาน ผู้รับจ้าง และผู้ให้บริการภายนอกที่เกี่ยวข้องกับบริการสำคัญ
- สถานการณ์ภัยธรรมชาติและภัยพิบัติที่ทำให้สถานที่ ระบบ หรือบุคลากรไม่พร้อมใช้งาน

### 2.2 นอกขอบเขตโดยตรง
- แผนป้องกันอัคคีภัย/ความปลอดภัยชีวิตฉบับปฏิบัติการละเอียดของอาคาร (อ้างอิงแผนความปลอดภัยสถานที่)
- รายละเอียดเทคนิค runbook รายระบบทั้งหมด (ให้จัดทำเป็นภาคผนวกหรือเอกสาร DR runbook ย่อย)

## 3. นิยามศัพท์

| คำศัพท์ | ความหมาย |
|---------|----------|
| **BCP** | แผนความต่อเนื่องทางธุรกิจ สำหรับรักษากระบวนการสำคัญให้เดินหน้าได้ |
| **DRP / DR** | แผนกู้คืนจากภัยพิบัติ สำหรับกู้ระบบ IT สถานที่ และข้อมูล |
| **BIA** | การวิเคราะห์ผลกระทบทางธุรกิจ เพื่อจัดลำดับความสำคัญของกระบวนการ/ระบบ |
| **RTO** | ระยะเวลานานสุดที่ยอมให้ระบบหรือกระบวนการหยุดได้ |
| **RPO** | ปริมาณข้อมูลสูงสุดที่ยอมให้สูญหายได้ นับย้อนจากเวลาเกิดเหตุ |
| **MTPD** | ระยะเวลานานสุดที่กระบวนการหยุดแล้วองค์กรยังทนได้ |
| **Crisis Management Team (CMT)** | คณะจัดการวิกฤตระดับองค์กร |
| **Alternate Site** | สถานที่ปฏิบัติงานสำรอง |
| **Warm/Cold/Hot Site** | ระดับความพร้อมของสถานที่หรือระบบสำรอง |
| **Declaration** | การประกาศเปิดใช้แผน BCP/DR อย่างเป็นทางการ |

## 4. นโยบายและหลักการ

1. **ชีวิตและความปลอดภัยมาก่อน** — อพยพและคุ้มครองบุคคลก่อนกู้ทรัพย์สินหรือระบบ
2. **ธุรกิจสำคัญมาก่อน** — กู้คืนตามลำดับจาก BIA ไม่กู้ทุกอย่างพร้อมกันโดยไร้ลำดับ
3. **สำรองแยกสถานที่** — ข้อมูลสำรองและระบบสำคัญต้องไม่เสี่ยงจุดเดียวกับระบบหลัก
4. **สื่อสารชัดเจน** — มีผู้พูดแทนองค์กรคนเดียวในแต่ละช่วงวิกฤต
5. **ซ้อมแล้วจึงเชื่อได้** — แผนที่ไม่ได้ทดสอบถือว่ายังไม่พร้อมใช้
6. **เชื่อมกับแผน IR** — หากเหตุเป็นภัยไซเบอร์ ให้ใช้ร่วมกับ PROC-IR-001

## 6. การวิเคราะห์ผลกระทบทางธุรกิจ (BIA) — กรอบการจัดลำดับ

### 6.1 ระดับความสำคัญของกระบวนการ

| ระดับ | ความหมาย | แนวทาง |
|-------|----------|--------|
| **Critical (C1)** | หยุดทันทีส่งผลรุนแรงต่อชีวิต กฎหมาย รายได้หลัก หรือบริการลูกค้าสำคัญ | กู้เป็นลำดับแรก ต้องมี workaround ชัดเจน |
| **Major (C2)** | หยุดได้ไม่นาน แต่หากเกิน RTO จะกระทบสูง | กู้ลำดับสอง |
| **Important (C3)** | กระทบปานกลาง สามารถล่าช้าได้ในช่วงสั้น | กู้หลังระบบหลักเสถียร |
| **Supporting (C4)** | สนับสนุนทั่วไป | กู้เมื่อทรัพยากรเหลือ |

### 6.2 ตารางเป้าหมายการกู้คืน (ตัวอย่าง — ปรับตามองค์กร)

| กระบวนการ / ระบบ | ระดับ | RTO | RPO | Dependency หลัก |
|-------------------|-------|-----|-----|------------------|
| การสื่อสารฉุกเฉิน / ช่องทางติดต่อพนักงาน | C1 | 1 ชม. | 0–15 นาที | อีเมลสำรอง, โทรศัพท์, chat on-call |
| ระบบยืนยันตัวตนกลาง (IdP/SSO) | C1 | 2 ชม. | 15 นาที | DNS, MFA, directory |
| ระบบธุรกิจหลัก [ระบุชื่อ] | C1 | 4 ชม. | 1 ชม. | DB, App, Network |
| อีเมลองค์กร | C1/C2 | 4 ชม. | 1 ชม. | IdP, DNS |
| ไฟล์แชร์ / เอกสารสำคัญ | C2 | 8 ชม. | 4 ชม. | Backup, Storage |
| ระบบ HR / เงินเดือน | C2/C3 | 24–72 ชม. | 24 ชม. | ตามรอบจ่าย |
| ระบบพัฒนา/ทดสอบ | C4 | 1 สัปดาห์ | 24–48 ชม. | ไม่บล็อกบริการลูกค้า |

### 6.3 เกณฑ์ประเมินผลกระทบ

พิจารณาอย่างน้อย: ความปลอดภัยของบุคคล รายได้ กฎหมาย/สัญญา ชื่อเสียง การดำเนินงานของลูกค้า และผลกระทบลูกโซ่ต่อระบบอื่น

## 7. การประเมินความเสี่ยงและสถานการณ์ภัย (Threat Scenarios)

### 7.1 ภัยธรรมชาติที่ต้องเตรียมรับมือ

| สถานการณ์ | ผลกระทบที่เป็นไปได้ | แนวทางหลัก |
|-----------|----------------------|------------|
| **น้ำท่วม / ฝนหนักต่อเนื่อง** | เข้าไม่ถึงสำนักงาน ไฟฟ้า/เครือข่ายเสียหาย อุปกรณ์เสีย | ทำงานระยะไกล อพยพข้อมูล/อุปกรณ์สำคัญ เปิดสถานที่สำรอง |
| **พายุ / ลมแรง** | ไฟฟ้าดับ หลังคา/หน้าต่างเสียหาย สัญญาณสื่อสารขาด | ปิดระบบอย่างปลอดภัยก่อนเหตุ (ถ้ารู้ล่วงหน้า) ใช้ generator/cloud |
| **แผ่นดินไหว** | โครงสร้างอาคารเสี่ยง อพยพฉุกเฉิน | ชีวิตมาก่อน ห้ามกลับเข้าอาคารจนกว่าเจ้าหน้าที่ประกาศปลอดภัย |
| **อัคคีภัย / ควันไฟจากเหตุธรรมชาติหรืออาคาร** | สูญเสียสถานที่และอุปกรณ์ | อพยพ ใช้สำรองนอกสถานที่ |
| **อากาศร้อนจัด / มลพิษรุนแรง** | บุคลากรทำงานไม่ได้เต็มที่ ระบบระบายความร้อนศูนย์ข้อมูลเสี่ยง | ปรับรูปแบบทำงาน WFH สับเปลี่ยนกำลังคน |
| **โรคระบาดรุนแรง** | ขาดแคลนกำลังคนพร้อมกัน | ทีมสำรอง แบ่งแยกทีม (team split) ทำงานระยะไกล |

### 7.2 ภัยพิบัติอื่นที่เกี่ยวข้อง

- ไฟฟ้าดับระยะยาว / ระบบปรับอากาศศูนย์ข้อมูลล่ม
- สายสื่อสารหลักขาด
- ศูนย์ข้อมูลหรือผู้ให้บริการคลาวด์ระดับภูมิภาคล่ม
- แรนซัมแวร์หรือภัยไซเบอร์ที่ทำให้บริการหลักหยุด (ประสาน PROC-IR-001)
- ผู้ให้บริการสำคัญล้มเหลวพร้อมกัน

### 7.3 กลยุทธ์ลดความเสี่ยงล่วงหน้า

1. สำรองข้อมูลนอกสถานที่หรือคนละภูมิภาคกับระบบหลัก
2. มีช่องทางอินเทอร์เน็ต/สื่อสารสำรอง
3. จัดทีม关键สำคัญอย่างน้อย 2 คนที่ทำแทนกันได้
4. เอกสารแผนและรายชื่อติดต่อเข้าถึงได้แม้ SSO หลักล่ม
5. ประกันภัยและสัญญา vendor ที่กำหนด RTO/การชดเชยตามความเหมาะสม

## 8. เกณฑ์ประกาศใช้แผน (Declaration Criteria)

CMT ควรพิจารณาประกาศใช้ BCP/DR เมื่อเข้าเงื่อนไขอย่างน้อยหนึ่งข้อ

1. สถานที่หลักใช้ไม่ได้เกิน **4 ชั่วโมง** หรือมีแนวโน้มใช้ไม่ได้เกิน RTO ของกระบวนการ C1
2. ระบบ C1 หยุดและคาดว่ากู้ที่ระบบหลักไม่ทัน RTO
3. มีคำเตือนภัยธรรมชาติระดับที่ทางการแนะนำให้อพยพหรือหยุดปฏิบัติงาน
4. บุคลากรสำคัญจำนวนมากไม่สามารถทำงาน ณ สถานที่หลักได้พร้อมกัน
5. ผู้บริหารสั่งเปิดแผนจากสถานการณ์วิกฤตอื่น

**ผู้มีอำนาจประกาศ:** CMT Leader หรือผู้ได้รับมอบหมาย  
**ผู้มีอำนาจยกเลิกแผนกลับสู่ภาวะปกติ:** CMT Leader หลังได้รับยืนยันจาก Facility และ IT DR Lead

## 9. ขั้นตอนตอบสนองเมื่อเกิดภัยธรรมชาติ/ภัยพิบัติ

```text
1. Protect Life → 2. Assess Impact → 3. Declare BCP/DR (ถ้าเข้าเกณฑ์)
 → 4. Activate Teams & Comms → 5. Continuity Workarounds
 → 6. IT Disaster Recovery → 7. Resume Critical Business
 → 8. Stabilize & Return → 9. Review Lessons Learned
```

### 9.1 ระยะที่ 0–1 ชั่วโมง: ชีวิต ความปลอดภัย และการประเมินฉับพลัน

1. อพยพหรือเคลื่อนย้ายตามแผนความปลอดภัยสถานที่
2. ตรวจนับพนักงานในความดูแล (accountability) ผ่านหัวหน้าหน่วยงาน
3. ห้ามกลับเข้าพื้นที่เสี่ยงจนกว่า Facility/Safety หรือเจ้าหน้าที่รัฐอนุญาต
4. ประเมินเบื้องต้นว่าสถานที่ ไฟฟ้า เครือข่าย ระบบ และกำลังคนพร้อมหรือไม่
5. เปิดช่องทางสื่อสารฉุกเฉินของ CMT

### 9.2 ระยะประเมินและประกาศใช้แผน

1. CMT ประชุมสั้น (bridge call) เพื่อสรุปสถานการณ์
2. ตัดสินใจว่าจะทำงานระยะไกล เปิดสถานที่สำรอง หรือปิดบริการบางส่วน
3. ประกาศใช้แผนให้ผู้เกี่ยวข้องทราบ พร้อมรหัสเหตุ เช่น `BCP-YYYYMMDD-XXX`
4. แจ้ง Business Process Owners และ IT DR Lead เริ่มตามลำดับความสำคัญ

### 9.3 ระยะความต่อเนื่องทางธุรกิจ (Business Continuity)

1. เปิด workaround ของกระบวนการ C1 เช่น ใช้ฟอร์มสำรอง คิวงานแมนนวล ช่องทางติดต่อลูกค้าสำรอง
2. จัดกำลังคนและอุปกรณ์สำหรับทีมสำคัญ
3. บันทึกธุรกรรมที่ทำระหว่างภาวะฉุกเฉินเพื่อกลับไปปรับปรุงในระบบหลักภายหลัง
4. ติดตามสถานะบริการลูกค้าและข้อผูกพันตามสัญญา

### 9.4 ระยะกู้คืนระบบ IT (Disaster Recovery)

1. IT DR Lead ประเมินว่าระบบหลักกู้ได้หรือต้อง failover ไปสภาพแวดล้อมสำรอง
2. กู้ตามลำดับ dependency เช่น Network/DNS → Identity → Database → Application → Integration
3. ตรวจสอบความถูกต้องของข้อมูลเทียบกับ RPO
4. ทดสอบ smoke test ก่อนเปิดให้ผู้ใช้จริง
5. เฝ้าระวังเข้มข้นอย่างน้อย 24–72 ชั่วโมงหลังเปิดบริการ

### 9.5 ระยะกลับสู่ภาวะปกติ (Return to Normal)

1. ประเมินความพร้อมของสถานที่และระบบหลัก
2. วางแผน failback หากทำงานบนระบบสำรอง
3. สื่อสารกำหนดการกลับสำนักงาน/ระบบหลักล่วงหน้า
4. ปิดสถานะ BCP อย่างเป็นทางการ
5. จัดทำรายงานหลังเหตุและแผนปรับปรุง

## 10. กลยุทธ์สถานที่และกำลังคน

### 10.1 ทางเลือกสถานที่ปฏิบัติงาน

| ทางเลือก | ใช้เมื่อ | ข้อควรเตรียม |
|----------|---------|----------------|
| ทำงานระยะไกล (WFH) | สำนักงานใช้ไม่ได้แต่คนและบ้าน/เครือข่ายพร้อม | VPN/Zero Trust, โน้ตบุ๊ก, MFA, นโยบายข้อมูล |
| สถานที่สำรองขององค์กร | ต้องทำงานใกล้เคียงกันหรือใช้เอกสาร/อุปกรณ์เฉพาะ | ที่นั่ง เครือข่าย อุปกรณ์ผ่านเข้าอาคาร |
| Coworking / สถานที่ผู้ให้บริการ | สำรองระยะสั้น | สัญญาหรือการจองฉุกเฉิน รายชื่อผู้มีสิทธิ์เข้า |
| สำนักงานสาขาอื่น | มีสาขาในพื้นที่ปลอดภัยกว่า | สิทธิ์เข้าอาคาร เครือข่ายแขกแบบควบคุม |

### 10.2 Team Split / Cross-training

1. กระบวนการ C1 ต้องมีผู้ทำแทนได้อย่างน้อย 1 คน
2. หลีกเลี่ยงการรวมทีมสำคัญทั้งหมดไว้สถานที่เดียวในช่วงเตือนภัย
3. รักษาช่องทางติดต่อส่วนตัวสำรองของสมาชิกทีมวิกฤต

## 11. กลยุทธ์เทคโนโลยีและการสำรองข้อมูล

### 11.1 หลักการ DR ด้าน IT

1. สำรองข้อมูลตามรอบที่สอดคล้อง RPO ของแต่ละระบบ
2. เก็บสำเนาสำคัญอย่างน้อยหนึ่งชุดแยกสถานที่/ภูมิภาคจากระบบหลัก
3. ทดสอบการกู้คืนจริงเป็นระยะ ไม่ทดสอบแค่สถานะ job สำรองสำเร็จ
4. เอกสาร runbook การกู้แต่ละระบบ C1/C2
5. เข้ารหัสข้อมูลสำรองและควบคุมสิทธิ์การเข้าถึง

### 11.2 ลำดับการกู้ระบบแนะนำ

1. สื่อสารและช่องทางสั่งการของทีมวิกฤต
2. DNS / Network / Internet egress สำรอง
3. Identity Provider / Directory / MFA
4. ระบบสำรองข้อมูลและที่เก็บข้อมูลหลัก
5. ฐานข้อมูลระบบธุรกิจสำคัญ
6. แอปพลิเคชันและบริการลูกค้า
7. ระบบสนับสนุน (monitoring, ticketing, HR)

### 11.3 เป้าหมายโครงสร้างพื้นฐานสำรอง

| องค์ประกอบ | แนวทางแนะนำ |
|------------|--------------|
| Compute/App | Hot/Warm standby หรือ IaC พร้อมสร้างในอีก region |
| Database | Replication ตาม RPO พร้อมขั้นตอน promote |
| Backup | รายวัน + incremental ตามความเสี่ยง และมี offline/immutable ตามความเหมาะสม |
| Endpoint | โน้ตบุ๊กมาตรฐานที่เข้า VPN ได้ ภาพรวม inventory ชัดเจน |

## 12. การสื่อสารในภาวะวิกฤต

### 12.1 กลุ่มเป้าหมาย

- พนักงานและครอบครัว (กรณีภัยธรรมชาติรุนแรง)
- ผู้บริหารและคณะกรรมการ
- ลูกค้า คู่ค้า ซัพพลายเออร์
- ผู้ให้บริการ IT / สถานที่
- สื่อมวลชนและสาธารณะ (เมื่อจำเป็น)
- หน่วยงานรัฐที่เกี่ยวข้อง

### 12.2 กฎการสื่อสาร

1. ข้อมูลสถานการณ์อย่างเป็นทางการออกผ่าน Communications Lead เท่านั้น
2. หลีกเลี่ยงการคาดเดา timeline หากยังไม่ยืนยัน
3. อัปเดตสถานะตามรอบ เช่น ทุก 1–2 ชั่วโมงในช่วงแรกของเหตุ P1
4. ใช้หลายช่องทาง: SMS/โทรศัพท์, chat ฉุกเฉิน, อีเมลสำรอง, เว็บสถานะบริการ
5. บันทึกข้อความที่เผยแพร่ทุกครั้ง

### 12.3 ข้อความต้นแบบสั้น ๆ

**ถึงพนักงาน**
> ขณะนี้องค์กรเปิดใช้แผนความต่อเนื่องเนื่องจาก [เหตุการณ์] กรุณาไม่เดินทางเข้าพื้นที่สำนักงานจนกว่าจะมีประกาศเพิ่มเติม ทีมวิกฤตจะอัปเดตอีกครั้งภายใน [เวลา] หากต้องการความช่วยด่วนติดต่อ [ช่องทาง]

**ถึงลูกค้า**
> ขณะนี้บริการ [ชื่อบริการ]ได้รับผลกระทบจาก [เหตุการณ์] ทีมงานกำลังดำเนินการเพื่อกู้คืน โดยจะแจ้งความคืบหน้าผ่าน [ช่องทาง] เป็นระยะ

## 13. การประสานงานกับภัยไซเบอร์และเหตุ IT

หากเหตุที่ทำให้ต้องใช้ BCP มีสาเหตุหรือองค์ประกอบทางไซเบอร์

1. เปิดเคสร่วมตาม PROC-IR-001
2. อย่ากู้ระบบจากสำรองที่อาจติดมัลแวร์โดยไม่ตรวจสอบ
3. ให้ Incident Commander กับ IT DR Lead ประสานลำดับการกักกันและกู้คืน
4. หากมีข้อมูลส่วนบุคคลรั่วไหลระหว่างเหตุ ประสาน DPO ตามขั้นตอน PDPA

## 14. แผนการซ้อมและทดสอบ

| ประเภทการทดสอบ | ความถี่แนะนำ | ขอบเขต |
|----------------|-------------|--------|
| Tabletop (ซ้อมบนโต๊ะ) | อย่างน้อยปีละ 1 ครั้ง | สถานการณ์น้ำท่วม/ไฟไหม้/ศูนย์ข้อมูลล่ม |
| Call-tree / Notification test | ปีละ 2 ครั้ง | ทดสอบการติดต่อ CMT และหัวหน้าหน่วยงาน |
| Backup restore test | อย่างน้อยรายไตรมาสสำหรับระบบ C1 | กู้ไฟล์/DB บางส่วนหรือเต็มตามแผน |
| Technical DR failover | อย่างน้อยปีละ 1 ครั้ง | Failover ระบบสำคัญไปสภาพแวดล้อมสำรอง |
| Work-from-alternate test | ปีละ 1 ครั้ง | ให้ทีมสำคัญทำงานนอกสถานที่หลักครึ่งวัน/เต็มวัน |

หลังซ้อมทุกครั้งต้องมีบันทึกผล ช่องว่าง และแผนปรับปรุงภายใน 30 วัน

## 21. ภาคผนวก ก — Playbook ภัยธรรมชาติอย่างย่อ

### ก.1 น้ำท่วม / เตือนภัยล่วงหน้าได้
1. ติดตามประกาศทางการและประเมินความเสี่ยงสถานที่
2. สั่งให้พนักงานย้ายโน้ตบุ๊กและเอกสารสำคัญออกจากพื้นที่เสี่ยง
3. ยืนยันสถานะสำรองข้อมูลล่าสุดและไฟฟ้า/generator
4. เตรียมประกาศ WFH หรือสถานที่สำรอง
5. หากน้ำเริ่มกระทบอาคาร ให้ตัดไฟฟ้าอย่างปลอดภัยโดยผู้มีหน้าที่ และเปิด BCP

### ก.2 แผ่นดินไหว / เหตุไม่มีคำเตือน
1. ป้องกันตัว อพยพตามจุดรวมพล
2. ตรวจนับคน ห้ามกลับเข้าอาคารเอง
3. CMT ประเมินความเสียหายและระบบสื่อสาร
4. เปิดช่องทาง WFH/สถานที่สำรองถ้าสำนักงานใช้ไม่ได้
5. IT ตรวจศูนย์ข้อมูล/คลาวด์ และกู้ตามลำดับ C1

### ก.3 พายุไฟฟ้าดับระยะยาว
1. ประเมินอายุการสำรองไฟของเครื่องสำคัญ
2. ปิดระบบอย่างมีลำดับหากไฟฟ้าสำรองใกล้หมด
3. สื่อสารกำหนด downtime ให้ผู้ใช้และลูกค้า
4. เมื่อไฟฟ้ากลับมา ตรวจความพร้อมก่อนเปิดบริการทีละชั้น
