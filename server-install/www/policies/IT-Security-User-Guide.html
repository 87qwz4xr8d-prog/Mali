IT Security — Quick Reference

Document No. GUIDE-ITSEC-001 Rev. 00
สถานะ Controlled Document (ISO 9001 / STD-QMS-001)

เอกสารนี้อ่านคู่กับ - นโยบายการรักษาความปลอดภัยระบบเทคโนโลยีสารสนเทศ (POL-ITSEC-001) - นโยบายคุ้มครองข้อมูลส่วนบุคคล (POL-PDPA-001) - มาตรฐานรหัสผ่านและการพิสูจน์ตัวตน (STD-ITSEC-001) - มาตรฐานการจัดประเภทข้อมูล (STD-ITSEC-002) - มาตรฐานการควบคุมเอกสาร (STD-QMS-001) - ขั้นตอนการจัดการเหตุการณ์ด้านความปลอดภัย (PROC-IR-001) - ขั้นตอนการขอ/เปลี่ยนแปลง/เพิกถอนสิทธิ์ผู้ใช้ (PROC-IAM-001) - แผนความต่อเนื่องทางธุรกิจและกู้คืนจากภัยพิบัติ (PROC-BCP-001) - แบบฟอร์มขอยกเว้น (FORM-EXC-001) - ทะเบียนแม่เอกสาร (FORM-QMS-001) - แบบฟอร์มขอเปลี่ยนแปลงเอกสาร (FORM-QMS-002)

สิ่งที่ต้องทำเสมอ

  1. ล็อกหน้าจอ เมื่อเดินออกจากเครื่อง
  2. ใช้ MFA ทุกครั้งที่ระบบรองรับ โดยเฉพาะอีเมล VPN และระบบสำคัญ
  3. เก็บรหัสผ่านเป็นความลับ — ห้ามแชร์ ห้ามติดบนจอ
  4. สงสัยลิงก์/ไฟล์แนบ จากอีเมลหรือแชทที่ไม่คุ้นเคย — อย่าคลิก และแจ้งฝ่าย IT
  5. ใช้เฉพาะซอฟต์แวร์และคลาวด์ที่องค์กรอนุมัติ สำหรับงานและข้อมูลองค์กร
  6. อย่าส่งข้อมูลลับหรือข้อมูลส่วนบุคคล เข้าเครื่องมือ AI / แชทภายนอก ที่ไม่ได้รับอนุญาต
  7. แจ้งทันที เมื่ออุปกรณ์หาย สงสัยบัญชีถูกละเมิด หรือพบเหตุผิดปกติ

รหัสผ่านและ MFA (สรุปจาก STD-ITSEC-001)

หัวข้อ เกณฑ์ขั้นต่ำ
ความยาวรหัสผ่านทั่วไป อย่างน้อย 12 ตัวอักษร
บัญชีสิทธิพิเศษ อย่างน้อย 16 ตัวอักษร
MFA บังคับกับอีเมล VPN คลาวด์ และระบบสำคัญ
ห้าม แชร์รหัสผ่าน ใช้รหัสง่าย ๆ หรือใช้ซ้ำกับบัญชีส่วนตัว
เมื่อสงสัยว่ารั่ว เปลี่ยนทันทีแล้วแจ้งฝ่าย IT

รายละเอียดเต็มดูที่ Password-Authentication-Standard.md

สิทธิ์การเข้าถึง

  • ขอสิทธิ์เท่าที่งานจำเป็น เท่านั้น ผ่านช่องทางที่องค์กรกำหนด
  • เมื่อย้ายหน่วยงานหรือลาออก สิทธิ์จะถูกเพิกถอน — ห้ามใช้บัญชีของผู้อื่น
  • บัญชีแอดมินใช้เฉพาะงานดูแลระบบ ห้ามใช้ทำงานประจำวัน
  • สิทธิ์ชั่วคราว/ผู้รับเหมาต้องมีวันหมดอายุทุกครั้ง

รายละเอียดเต็มดูที่ User-Access-Management-Procedure.md

ข้อมูลและการจัดประเภท

ระดับ ทำได้ ห้าม
สาธารณะ เผยแพร่ได้หลังตรวจสอบ เผยแพร่ข้อมูลผิด/ทำให้เข้าใจผิด
ภายใน ใช้ในองค์กร ส่งออกภายนอกโดยไม่จำเป็น
ลับ ส่งผ่านช่องทางที่อนุมัติเท่านั้น แชร์กว้าง หรือเก็บในเครื่องส่วนตัว
ลับที่สุด เข้าถึงเฉพาะผู้ได้รับอนุญาต คัดลอก/ส่งต่อโดยไม่มีอำนาจ

จำง่าย: ข้อมูลส่วนบุคคลทั่วไป = อย่างน้อย ลับ | ข้อมูลอ่อนไหว/คีย์เข้ารหัส = ลับที่สุด | ไม่แน่ใจ = จัดเป็น ลับ ก่อน

ทั่วไป (สงสัยฟิชชิง, ขอคำปรึกษา) [ระบุ: Helpdesk / อีเมล]

เมื่อแจ้ง ให้ระบุ: เวลาที่พบ, ระบบ/บัญชีที่เกี่ยวข้อง, สิ่งที่เกิดขึ้น, ผลกระทบเบื้องต้น (ถ้าทราบ)

รายละเอียดขั้นตอนเต็มดูที่ Incident-Response-Procedure.md

จำไว้: อย่าปกปิดเหตุ อย่าลบหลักฐานเอง และรอคำสั่งทีม IR ก่อนดำเนินการเพิ่มเติม

เมื่อเกิดภัยธรรมชาติหรือสถานที่ทำงานใช้ไม่ได้

  1. ชีวิตมาก่อน — อพยพตามจุดรวมพล ห้ามกลับเข้าพื้นที่เสี่ยงเอง
  2. ติดตามประกาศจากหัวหน้างาน / ทีมวิกฤต เท่านั้น
  3. เตรียมทำงานระยะไกลผ่านช่องทางที่องค์กรอนุมัติ (VPN/MFA)
  4. อย่านำข้อมูลระดับลับขึ้นไปไปไว้คลาวด์ส่วนตัวโดยไม่ได้รับอนุญาต

รายละเอียดเต็มดูที่ Business-Continuity-Disaster-Recovery-Plan.md

การขอยกเว้นนโยบายความปลอดภัย

หากไม่สามารถปฏิบัติตามนโยบายได้ชั่วคราว ให้ใช้แบบฟอร์ม Security-Policy-Exception-Form.md (FORM-EXC-001)
ต้องระบุเหตุผล ระยะเวลา มาตรการชดเชย และรออนุมัติก่อนดำเนินการ (ยกเว้นกรณีฉุกเฉินตามที่กำหนด)

การฝ่าฝืน

การไม่ปฏิบัติตามนโยบายอาจมีบทลงโทษทางวินัย และอาจมีความรับผิดตามกฎหมายหากก่อความเสียหายหรือละเมิดข้อมูลส่วนบุคคล
