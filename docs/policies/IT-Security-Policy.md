## 1. วัตถุประสงค์

นโยบายฉบับนี้จัดทำขึ้นเพื่อ

1. กำหนดกรอบและแนวทางในการรักษาความมั่นคงปลอดภัยของระบบเทคโนโลยีสารสนเทศและข้อมูลขององค์กร
2. ปกป้องความลับ (Confidentiality) ความถูกต้องครบถ้วน (Integrity) และความพร้อมใช้งาน (Availability) ของข้อมูลและระบบ
3. ลดความเสี่ยงจากภัยคุกคามทางไซเบอร์ การเข้าถึงโดยไม่ได้รับอนุญาต การรั่วไหล และการสูญหายของข้อมูล
4. สร้างความตระหนักและกำหนดหน้าที่ความรับผิดชอบของผู้มีส่วนเกี่ยวข้องทุกระดับ
5. ให้สอดคล้องกับกฎหมายและมาตรฐานที่เกี่ยวข้อง ได้แก่
   - พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)
   - พระราชบัญญัติการรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. 2562
   - หลักการตามมาตรฐาน ISO/IEC 27001:2022 (ตามที่องค์กรนำไปปรับใช้)

## 2. ขอบเขต

นโยบายนี้ใช้บังคับกับ

- พนักงาน ลูกจ้าง ที่ปรึกษา ผู้รับเหมา นักศึกษาฝึกงาน และบุคคลภายนอกที่ได้รับสิทธิเข้าใช้งานระบบขององค์กร
- ระบบคอมพิวเตอร์ เครือข่าย คลาวด์ แอปพลิเคชัน อุปกรณ์ปลายทาง อุปกรณ์เครือข่าย และสื่อจัดเก็บข้อมูลทั้งหมดที่เป็นขององค์กรหรือใช้เพื่อภารกิจขององค์กร
- ข้อมูลทุกประเภทที่องค์กรเป็นเจ้าของ ครอบครอง ประมวลผล หรือดูแล รวมถึงข้อมูลส่วนบุคคล ข้อมูลธุรกิจ และข้อมูลความลับทางการค้า
- การทำงานทั้งในสถานที่ทำงาน ระยะไกล (remote) และนอกสถานที่

## 3. นิยามศัพท์

| คำศัพท์ | ความหมาย |
|---------|----------|
| **สารสนเทศ / ข้อมูล** | ข้อเท็จจริง ตัวเลข ข้อความ ภาพ เสียง หรือข้อมูลอิเล็กทรอนิกส์ใด ๆ ที่องค์กรจัดเก็บหรือประมวลผล |
| **ระบบสารสนเทศ** | ฮาร์ดแวร์ ซอฟต์แวร์ เครือข่าย ฐานข้อมูล และบริการที่เกี่ยวข้องที่ใช้ประมวลผลข้อมูล |
| **ผู้ใช้งาน** | บุคคลที่ได้รับสิทธิเข้าใช้งานระบบสารสนเทศขององค์กร |
| **เหตุการณ์ด้านความปลอดภัย (Security Incident)** | เหตุการณ์ที่ส่งผลกระทบหรืออาจส่งผลกระทบต่อความมั่นคงปลอดภัยของข้อมูลหรือระบบ |
| **ข้อมูลส่วนบุคคล** | ข้อมูลเกี่ยวกับบุคคลซึ่งทำให้สามารถระบุตัวบุคคลนั้นได้ตามนิยามใน พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล |
| **สิทธิพิเศษ (Privileged Access)** | สิทธิระดับผู้ดูแลระบบหรือสิทธิที่สูงกว่าผู้ใช้งานทั่วไป |

## 4. หลักการความมั่นคงปลอดภัยสารสนเทศ

องค์กรยึดหลัก **CIA Triad** ดังนี้

1. **Confidentiality (ความลับ)** — เข้าถึงข้อมูลได้เฉพาะผู้มีสิทธิและมีเหตุอันควร
2. **Integrity (ความถูกต้องครบถ้วน)** — ป้องกันการแก้ไข ทำลาย หรือปลอมแปลงข้อมูลโดยไม่ได้รับอนุญาต
3. **Availability (ความพร้อมใช้งาน)** — ระบบและข้อมูลพร้อมใช้งานเมื่อมีความจำเป็นทางธุรกิจ

รวมถึงหลักการเพิ่มเติม ได้แก่ การพิสูจน์ตัวตน (Authentication) การให้อนุญาต (Authorization) การบันทึกตรวจสอบ (Accountability / Audit) และการไม่ปฏิเสธความรับผิด (Non-repudiation)

## 5. บทบาทและหน้าที่ความรับผิดชอบ

### 5.1 ผู้บริหารสูงสุด / คณะกรรมการ
- อนุมัติและสนับสนุนนโยบาย รวมถึงจัดสรรงบประมาณและทรัพยากร
- กำกับดูแลความเสี่ยงด้านไซเบอร์ในระดับองค์กร

### 5.2 ผู้บริหารฝ่ายเทคโนโลยีสารสนเทศ (CIO / IT Manager)
- นำนโยบายไปปฏิบัติ กำหนดมาตรฐานและแนวปฏิบัติที่เกี่ยวข้อง
- รายงานสถานะความเสี่ยงและเหตุการณ์สำคัญต่อผู้บริหาร

### 5.3 เจ้าหน้าที่ความมั่นคงปลอดภัยสารสนเทศ (ISO / CISO)
- วางแผน ติดตาม และปรับปรุงมาตรการความปลอดภัย
- ประสานงานการจัดการเหตุการณ์ การประเมินความเสี่ยง และการอบรม
- ทบทวนนโยบายและเอกสารที่เกี่ยวข้องเป็นระยะ

### 5.4 เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) *(ถ้ามี)*
- ให้คำปรึกษาด้านการคุ้มครองข้อมูลส่วนบุคคลตาม PDPA
- ประสานงานกรณีเกิดเหตุละเมิดข้อมูลส่วนบุคคล

### 5.5 ผู้ดูแลระบบ (System Administrators)
- ติดตั้ง กำหนดค่า และดูแลระบบตามมาตรฐานความปลอดภัย
- จัดการสิทธิ์ผู้ใช้ บันทึก log และสำรองข้อมูลตามที่กำหนด

### 5.6 ผู้ใช้งานทุกคน
- ปฏิบัติตามนโยบาย แนวปฏิบัติ และข้อกำหนดด้านความปลอดภัย
- รายงานเหตุการณ์หรือพฤติกรรมที่น่าสงสัยโดยเร็ว
- รักษาความลับของบัญชีผู้ใช้ รหัสผ่าน และข้อมูลที่เข้าถึงได้

### 5.7 ผู้ให้บริการภายนอก / พันธมิตร
- ปฏิบัติตามข้อกำหนดความปลอดภัยในสัญญาและข้อตกลงการประมวลผลข้อมูล
- ไม่เข้าถึงหรือใช้ข้อมูลเกินขอบเขตที่ได้รับอนุญาต

## 6. นโยบายย่อยและมาตรการควบคุม

### 6.1 การจัดประเภทและการจัดการข้อมูล (Data Classification & Handling)

ข้อมูลต้องได้รับการจัดประเภทอย่างน้อยดังนี้

| ระดับ | ตัวอย่าง | แนวทางปฏิบัติหลัก |
|-------|----------|-------------------|
| **ลับที่สุด (Restricted)** | ข้อมูลส่วนบุคคลอ่อนไหว ข้อมูลการเงินสำคัญ คีย์เข้ารหัส | จำกัดสิทธิ์สูงสุด เข้ารหัสทั้งขณะจัดเก็บและส่งผ่าน มีบันทึกการเข้าถึง |
| **ลับ (Confidential)** | ข้อมูลธุรกิจภายใน เอกสารสัญญา | เข้าถึงตาม Need-to-know ห้ามส่งออกโดยไม่ได้รับอนุญาต |
| **ภายใน (Internal)** | คู่มือภายใน ประกาศองค์กร | ใช้ภายในองค์กรเท่านั้น |
| **สาธารณะ (Public)** | ข้อมูลเผยแพร่ทั่วไป | ตรวจสอบความถูกต้องก่อนเผยแพร่ |

ผู้ใช้งานต้องไม่เปิดเผย คัดลอก หรือส่งต่อข้อมูลในระดับลับ/ลับที่สุดโดยไม่มีอำนาจหรือช่องทางที่ได้รับอนุญาต

### 6.2 การควบคุมการเข้าถึง (Access Control)

1. ให้สิทธิ์ตามหลัก **Least Privilege** และ **Need-to-Know**
2. บัญชีผู้ใช้ต้องเป็นรายบุคคล ห้ามใช้บัญชีร่วมกัน (ยกเว้นกรณีที่ได้รับอนุมัติและมีการควบคุมเพิ่มเติม)
3. ต้องมีการพิสูจน์ตัวตนที่รัดกุม เช่น รหัสผ่านที่แข็งแรง และ **Multi-Factor Authentication (MFA)** สำหรับระบบสำคัญ การเข้าถึงระยะไกล และบัญชีสิทธิพิเศษ
4. ทบทวนสิทธิ์ผู้ใช้เป็นระยะ และเพิกถอนสิทธิ์ทันทีเมื่อพ้นสภาพ พ้นหน้าที่ หรือเปลี่ยนบทบาท
5. บัญชีสิทธิพิเศษต้องมีการควบคุมเข้มงวด มีการบันทึกการใช้งาน และแยกจากบัญชีใช้งานประจำวัน

### 6.3 การจัดการรหัสผ่านและข้อมูลรับรอง (Credentials)

1. รหัสผ่านต้องมีความยาวและความซับซ้อนตามมาตรฐานที่องค์กรกำหนด และห้ามใช้รหัสผ่านซ้ำกับระบบภายนอก
2. ห้ามแบ่งปันรหัสผ่าน เขียนติดอุปกรณ์ หรือเก็บในที่ที่ไม่ปลอดภัย
3. หากสงสัยว่ารหัสผ่านรั่วไหล ต้องเปลี่ยนทันทีและแจ้งฝ่าย IT
4. ห้ามฝังรหัสผ่านหรือ API key ในซอร์สโค้ดแบบเปิดเผย ต้องใช้ระบบจัดการความลับ (secrets management)

### 6.4 ความปลอดภัยของเครือข่าย (Network Security)

1. แบ่งแยกเครือข่ายตามความเสี่ยง (segmentation) และจำกัดการเชื่อมต่อระหว่างโซน
2. ใช้ไฟร์วอลล์ VPN และการเข้ารหัสช่องทางสื่อสารตามความเหมาะสม
3. ห้ามเชื่อมต่ออุปกรณ์ที่ไม่ได้รับอนุญาตเข้าสู่เครือข่ายองค์กร
4. ตรวจสอบและปิดพอร์ต/บริการที่ไม่จำเป็น
5. เฝ้าระวังทราฟฟิกและเหตุผิดปกติอย่างต่อเนื่อง

### 6.5 ความปลอดภัยของอุปกรณ์ปลายทาง (Endpoint Security)

1. อุปกรณ์ขององค์กรต้องติดตั้งระบบป้องกันมัลแวร์ อัปเดตระบบปฏิบัติการ และเปิดการเข้ารหัสดิสก์ตามที่กำหนด
2. ห้ามปิดหรือถอดซอฟต์แวร์รักษาความปลอดภัยโดยไม่ได้รับอนุญาต
3. การนำอุปกรณ์ส่วนตัวมาใช้ทำงาน (BYOD) ต้องได้รับอนุมัติและปฏิบัติตามข้อกำหนดที่องค์กรกำหนด
4. ล็อกหน้าจอเมื่อไม่ใช้งาน และตั้งค่าหมดเวลาอัตโนมัติ
5. เมื่ออุปกรณ์สูญหายหรือถูกขโมย ต้องแจ้งฝ่าย IT ทันทีเพื่อระงับการเข้าถึงและลบข้อมูลระยะไกล (หากทำได้)

### 6.6 ความปลอดภัยของแอปพลิเคชันและการพัฒนา (Application & Secure Development)

1. พัฒนาและทดสอบระบบตามแนวทาง Secure SDLC
2. ตรวจสอบช่องโหว่ก่อนขึ้นใช้งานจริง (เช่น code review, dependency check, security testing ตามระดับความเสี่ยง)
3. แยกสภาพแวดล้อม Development / Test / Production อย่างชัดเจน
4. ห้ามใช้ข้อมูลส่วนบุคคลจริงในสภาพแวดล้อมทดสอบโดยไม่มีมาตรการปกป้องที่เหมาะสม (เช่น การทำให้ไม่ระบุตัวตน)
5. จัดการช่องโหว่และแพตช์ตามระดับความรุนแรงภายในระยะเวลาที่กำหนด

### 6.7 การเข้ารหัสข้อมูล (Cryptography)

1. ใช้มาตรฐานการเข้ารหัสที่เป็นที่ยอมรับและเป็นปัจจุบัน
2. เข้ารหัสข้อมูลสำคัญทั้งขณะจัดเก็บ (at rest) และขณะส่งผ่าน (in transit) ตามระดับความเสี่ยง
3. บริหารจัดการกุญแจเข้ารหัสอย่างปลอดภัย มีการหมุนเวียนและเพิกถอนเมื่อจำเป็น
4. ห้ามใช้算法หรือโปรโตคอลที่ล้าสมัยซึ่งมีความเสี่ยงสูง

### 6.8 การสำรองข้อมูลและการกู้คืน (Backup & Recovery)

1. สำรองข้อมูลสำคัญอย่างสม่ำเสมอตามตารางที่กำหนด และเก็บสำเนาอย่างน้อยส่วนหนึ่งแยกจากระบบหลัก
2. ทดสอบการกู้คืนข้อมูลเป็นระยะเพื่อยืนยันความพร้อมใช้งาน
3. ปกป้องสื่อสำรองด้วยการควบคุมการเข้าถึงและการเข้ารหัสตามความเหมาะสม
4. กำหนด RTO / RPO ของระบบสำคัญให้สอดคล้องกับความต่อเนื่องทางธุรกิจ

### 6.9 การจัดการเหตุการณ์ด้านความปลอดภัย (Incident Management)

1. ผู้พบเห็นเหตุผิดปกติต้องแจ้งช่องทางที่กำหนดโดยเร็ว เช่น ฝ่าย IT / Security / Helpdesk
2. มีขั้นตอนการตรวจจับ วิเคราะห์ กักกัน กู้คืน และบันทึกบทเรียนหลังเกิดเหตุ (post-incident review)
3. เหตุละเมิดข้อมูลส่วนบุคคลต้องประเมินและดำเนินการตาม PDPA รวมถึงแจ้ง สำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล ภายในกำหนดเวลาตามกฎหมายเมื่อเข้าเกณฑ์
4. ห้ามปกปิดเหตุการณ์ด้านความปลอดภัย

**ตัวอย่างเหตุที่ต้องแจ้ง:** การเข้าถึงโดยไม่ได้รับอนุญาต มัลแวร์/แรนซัมแวร์ ฟิชชิงที่สำเร็จ การสูญหายของอุปกรณ์ที่มีข้อมูลองค์กร การรั่วไหลของข้อมูล การโจมตีทำให้ระบบหยุดชะงัก

### 6.10 ความต่อเนื่องทางธุรกิจ (Business Continuity & Disaster Recovery)

1. จัดทำและทบทวนแผน BCP/DR สำหรับระบบและกระบวนการสำคัญ
2. ทดสอบแผนเป็นระยะ และปรับปรุงตามผลการทดสอบ
3. กำหนดช่องทางสื่อสารและผู้รับผิดชอบเมื่อเกิดเหตุฉุกเฉิน

### 6.11 ความปลอดภัยทางกายภาพ (Physical Security)

1. จำกัดการเข้าถึงห้องเซิร์ฟเวอร์ ศูนย์ข้อมูล และพื้นที่จัดเก็บอุปกรณ์สำคัญ
2. บันทึกการเข้า-ออกพื้นที่สำคัญ
3. ป้องกันความเสียหายจากไฟฟ้า อุณหภูมิ น้ำ และอัคคีภัยตามความเหมาะสม
4. ทำลายหรือทำให้ข้อมูลบนสื่อจัดเก็บไม่สามารถกู้คืนได้ก่อนจำหน่าย ทิ้ง หรือส่งซ่อม

### 6.12 การใช้งานอินเทอร์เน็ต อีเมล และเครื่องมือสื่อสาร

1. ใช้อีเมลและอินเทอร์เน็ตเพื่อภารกิจขององค์กรเป็นหลัก
2. ระวังฟิชชิง ลิงก์และไฟล์แนบจากแหล่งไม่น่าเชื่อถือ
3. ห้ามส่งข้อมูลลับผ่านช่องทางที่ไม่เข้ารหัสหรือไม่ได้รับอนุญาต
4. ห้ามติดตั้งซอฟต์แวร์เถื่อน หรือใช้บริการคลาวด์ส่วนบุคคลสำหรับเก็บข้อมูลองค์กรโดยไม่ได้รับอนุญาต
5. การใช้ Generative AI / เครื่องมือภายนอกต้องไม่ส่งข้อมูลลับหรือข้อมูลส่วนบุคคลเข้าสู่ระบบที่ไม่ได้รับอนุมัติ

### 6.13 ผู้ให้บริการภายนอกและบุคคลที่สาม (Third-Party Security)

1. ประเมินความเสี่ยงด้านความปลอดภัยก่อนว่าจ้างหรือเชื่อมต่อระบบกับบุคคลที่สาม
2. กำหนดข้อกำหนดด้านความปลอดภัยและการคุ้มครองข้อมูลในสัญญา
3. จำกัดสิทธิ์การเข้าถึงเท่าที่จำเป็น และเพิกถอนเมื่อสิ้นสุดสัญญา
4. ติดตามการปฏิบัติตามข้อกำหนดเป็นระยะตามระดับความเสี่ยง

### 6.14 การบันทึกและการตรวจสอบ (Logging & Monitoring)

1. เปิดใช้งานและเก็บรักษา log ของระบบสำคัญให้เพียงพอต่อการตรวจสอบย้อนหลัง
2. ป้องกันการแก้ไขหรือลบ log โดยไม่ได้รับอนุญาต
3. ตรวจสอบ log และสัญญาณเตือนอย่างสม่ำเสมอ
4. กำหนดระยะเวลาเก็บรักษา log ให้สอดคล้องกับกฎหมายและนโยบายภายใน

### 6.15 การสร้างความตระหนักและการอบรม (Awareness & Training)

1. ผู้ใช้งานใหม่ต้องได้รับการอบรมด้านความปลอดภัยก่อนหรือเมื่อเริ่มใช้งานระบบ
2. จัดอบรมทบทวนอย่างน้อยปีละ 1 ครั้ง และเมื่อมีภัยคุกคามรูปแบบใหม่ที่สำคัญ
3. อาจมีการทดสอบความตระหนัก เช่น การจำลองฟิชชิง ตามความเหมาะสม

### 6.16 การคุ้มครองข้อมูลส่วนบุคคล (PDPA)

1. เก็บ ใช้ เปิดเผยข้อมูลส่วนบุคคลเท่าที่จำเป็นตามวัตถุประสงค์ที่ชอบด้วยกฎหมาย
2. ใช้มาตรการรักษาความปลอดภัยที่เหมาะสมกับความเสี่ยงของข้อมูล
3. จำกัดการเข้าถึงข้อมูลส่วนบุคคลเฉพาะผู้ที่มีหน้าที่เกี่ยวข้อง
4. มีช่องทางรองรับการใช้สิทธิของเจ้าของข้อมูล
5. เมื่อเกิดเหตุละเมิด ต้องประเมินผลกระทบและดำเนินการตามขั้นตอนที่กฎหมายกำหนด

---

## 7. การยอมรับความเสี่ยงและการยกเว้น (Risk Acceptance & Exceptions)

1. การขอยกเว้นจากนโยบายต้องทำเป็นลายลักษณ์อักษร ระบุเหตุผล ระยะเวลา และมาตรการชดเชยความเสี่ยง
2. ต้องได้รับอนุมัติจากผู้มีอำนาจที่กำหนด และทบทวนการยกเว้นเป็นระยะ
3. ความเสี่ยงที่เหลืออยู่ (residual risk) ต้องได้รับการยอมรับอย่างเป็นทางการจากผู้รับผิดชอบที่เหมาะสม

---

## 8. การบังคับใช้และบทลงโทษ

1. ผู้ใช้งานทุกคนมีหน้าที่ปฏิบัติตามนโยบายนี้
2. การฝ่าฝืนอาจนำไปสู่มาตรการทางวินัยตามระเบียบขององค์กร รวมถึงการระงับสิทธิ์การใช้งาน และการดำเนินการทางกฎหมายหากก่อให้เกิดความเสียหายหรือละเมิดกฎหมาย
3. ความไม่รู้จักนโยบายไม่ถือเป็นข้ออ้างในการฝ่าฝืน

---

## 9. การทบทวนและปรับปรุงนโยบาย

1. ทบทวนนโยบายอย่างน้อย **ปีละ 1 ครั้ง**
2. ทบทวนทันทีเมื่อมีการเปลี่ยนแปลงด้านกฎหมาย เทคโนโลยี โครงสร้างองค์กร หรือเกิดเหตุการณ์ร้ายแรง
3. เวอร์ชันที่ได้รับการอนุมัติเท่านั้นถือเป็นเอกสารที่มีผลบังคับใช้
4. นโยบายที่เกี่ยวข้องหรือแนวปฏิบัติสนับสนุน ต้องสอดคล้องกับเอกสารฉบับนี้

## 10. เอกสารอ้างอิงและเอกสารที่เกี่ยวข้อง

แนะนำให้จัดทำหรืออ้างอิงเอกสารประกอบ ดังนี้

| รหัส (ตัวอย่าง) | ชื่อเอกสาร |
|-----------------|------------|
| STD-ITSEC-001 | มาตรฐานรหัสผ่านและการพิสูจน์ตัวตน |
| STD-ITSEC-002 | มาตรฐานการจัดประเภทข้อมูล |
| PROC-IR-001 | ขั้นตอนการจัดการเหตุการณ์ด้านความปลอดภัย |
| PROC-IAM-001 | ขั้นตอนการขอ/เปลี่ยนแปลง/เพิกถอนสิทธิ์ผู้ใช้ |
| PROC-BCP-001 | แผนความต่อเนื่องทางธุรกิจและกู้คืนจากภัยพิบัติ |
| POL-PDPA-001 | นโยบายคุ้มครองข้อมูลส่วนบุคคล |
| FORM-EXC-001 | แบบฟอร์มขอยกเว้นนโยบายความปลอดภัย |

**กฎหมายและมาตรฐานอ้างอิง**
- พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
- พระราชบัญญัติการรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. 2562
- ISO/IEC 27001:2022 — Information security, cybersecurity and privacy protection
- ISO/IEC 27002:2022 — Information security controls
